# Чек-лист перед коммерческим запуском

## 1. Контент и права
- [ ] Получить разрешение/лицензию на использование фотографий и рендеров каждого застройщика.
- [ ] Для каждого лота загрузить оригинальную планировку, площадь, комнатность, корпус, секцию, этаж и URL первоисточника.
- [ ] Сверить актуальность данных и зафиксировать дату последней проверки.
- [ ] Удалить любые карточки без подтверждённых сведений; не использовать демонстрационные схемы как реальные планы.
- [ ] Утвердить ставки работ, материалы, мебель, доп. опции, правила округления и срок действия сметы.

## 2. Техническая часть
- [ ] Развернуть серверную часть и базу данных (текущий проект — статический HTML/JS).
- [ ] Перенести админ-панель с localStorage на сервер с авторизацией, ролями и журналом изменений.
- [ ] Реализовать API каталога, импорт/обновление данных и проверку обязательных источников.
- [ ] Подключить серверную отправку заявок: CRM / почта / Telegram / иной согласованный канал.
- [ ] Защитить формы от спама; добавить валидацию, rate limit, CAPTCHA при необходимости.
- [ ] Настроить HTTPS, резервные копии, логирование ошибок и мониторинг.
- [ ] Настроить production-домен, аналитику и поисковую индексацию.

## 3. Юридическая часть
- [ ] Подготовить политику конфиденциальности, согласие на обработку персональных данных и отдельное согласие на рекламные сообщения, если применимо.
- [ ] Проверить требования российского законодательства о персональных данных, локализации и хранении заявок.
- [ ] Утвердить публичную оферту/условия расчёта и дисклеймер о предварительной смете.
- [ ] Не собирать персональные данные до подключения реального защищённого endpoint и публикации документов.

## 4. Тестирование
- [ ] Проверить мобильные устройства, браузеры и доступность клавиатурой.
- [ ] Проверить все страницы, формы, ссылки, избранное и восстановление конфигурации.
- [ ] Проверить смету на контрольных примерах и исключить двойной учёт материалов.
- [ ] Проверить сценарии пустого каталога, недоступной фотографии и ошибок сервера.
- [ ] Провести тестовые заявки и убедиться, что они реально доходят до ответственного менеджера.

## Текущий статус
Это улучшенный фронтенд-прототип с источниками и реальными фотографиями/рендерами с сайтов застройщиков. Он **не готов принимать реальные заявки и не должен считаться production-сервисом**, пока не выполнены пункты выше. Админка исходного проекта работает в браузере через localStorage и не является защищённой серверной админкой.

## Перед запуском аккаунтов и CRM
- [ ] Заполнить реквизиты оператора в `privacy.html` и `terms.html` (жёлтые поля), показать юристу.
- [ ] Подать уведомление об обработке персональных данных в Роскомнадзор (если требуется для вашей организации).
- [ ] Хостинг с серверами в РФ (152-ФЗ); подтвердить это в разделе 6 политики и убрать пометку.
- [ ] HTTPS (reverse proxy nginx/Caddy), запуск с `TRUST_PROXY=1`; HTTPS обязателен, иначе пароли идут открытым текстом.
- [ ] Сменить пароль администратора, создать аккаунты менеджеров через admin.html.
- [ ] Регулярная копия папки `data/` (там вся база).
- [ ] Желательно разместить шрифты и фото ЖК у себя — сейчас их браузер берёт у Google и застройщиков.
- [ ] Заменить примерные отзывы реальными (их можно скрыть или удалить в admin.html → Отзывы).
